# لاین‌یار | LineYar — مدیریت پروژه و خدمات فنی

**لاین‌یار (Service Project Manager)** یک برنامه فارسی و راست‌به‌چپ برای مدیریت مشتریان، پروژه‌های خدماتی، قرارداد، کار اضافه، پرداخت‌ها و گزارش کار روزانه است. این **PWA قابل نصب روی آیفون و اندروید**، اطلاعات را در مرورگر همان دستگاه نگه می‌دارد و پس از بارگذاری اولیه، از کار آفلاین پشتیبانی می‌کند.

[ورود به برنامه](https://hoseindashti1981.github.io/service-project-manager/) · [راهنمای تکنسین](docs/user-guide-fa.txt) · [نقشه فنی برای توسعه‌دهندگان و AI](docs/ai-project-map-fa.txt) · [نقشه راه](docs/roadmap.md)

> برای تکنسین‌ها، مجریان خدمات فنی و کسب‌وکارهایی که می‌خواهند مرجع اطلاعات مشتری و پروژه در یک برنامه باشد. حساب کاربری ابری و همگام‌سازی بین دستگاه‌ها هنوز پیاده‌سازی نشده‌اند.

## در این راهنما

قابلیت‌ها، شروع کار، منطق مالی، فاکتور، نصب و به‌روزرسانی، بکاپ و امنیت، راه‌اندازی توسعه، متغیرهای محیطی، انتشار، آزمون‌ها و پرسش‌های رایج.

## شروع کار

1. [برنامه را باز کنید](https://hoseindashti1981.github.io/service-project-manager/) و در **تنظیمات** نام و اطلاعات کسب‌وکار را وارد کنید.
2. در **مشتریان** نام و شماره مشتری را ذخیره کنید؛ ذخیره شماره در مخاطبان گوشی لازم نیست.
3. یک **پروژه جدید** بسازید؛ مبلغ توافق اولیه و تاریخ واقعی پروژه را مشخص کنید.
4. وضعیت را متناسب با مرحله کار تغییر دهید و خدمات پروژه را در صورت نیاز اضافه کنید.
5. با **فعالیت جدید** گزارش هر روز را ثبت کنید. لازم نیست هر روز برای کار مبلغ حساب کنید.
6. کار خارج از توافق را در **کار اضافه** ثبت کنید؛ دریافتی مشتری را در **مالی ← پرداخت** وارد کنید.
7. حساب پروژه را مرور کنید، در صورت نیاز فاکتور بسازید و از **تنظیمات ← بکاپ** فایل پشتیبان بگیرید.

برای معنی فیلدها و مثال‌های عملی، [راهنمای فارسی](docs/user-guide-fa.txt) را بخوانید یا دکمه «؟» داخل برنامه را لمس کنید.

## منطق مالی پروژه

همه مبالغ **تومان** هستند. منبع حساب پروژه قرارداد و کار اضافه است:

```text
جمع قابل دریافت = مبلغ قرارداد + جمع کارهای اضافه − تخفیف پروژه
مانده حساب      = جمع قابل دریافت − مجموع پرداخت‌های پروژه
```

| مثال | مبلغ به تومان |
| --- | ---: |
| قرارداد اولیه | ۲۰٬۰۰۰٬۰۰۰ |
| کار اضافه | ۳٬۰۰۰٬۰۰۰ |
| تخفیف پروژه | ۱٬۰۰۰٬۰۰۰ |
| جمع قابل دریافت | ۲۲٬۰۰۰٬۰۰۰ |
| مجموع پرداخت مشتری | ۱۰٬۰۰۰٬۰۰۰ |
| مانده بدهکاری مشتری | ۱۲٬۰۰۰٬۰۰۰ |

**بدهکار** یعنی مشتری مانده پرداخت‌نشده دارد؛ **تسویه‌شده** یعنی مانده صفر است؛ **بستانکار** یعنی مشتری بیشتر از مبلغ قابل دریافت پرداخت کرده است.

**فاکتور متصل به پروژه طلب را دوباره ایجاد نمی‌کند.** فاکتور سند همان حساب است. تخفیف، مالیات یا هزینه جانبی سند، حساب پروژه را خودکار تغییر نمی‌دهد؛ توافق واقعی باید در قرارداد، کار اضافه یا تخفیف پروژه نیز ثبت شود.

فاکتور **مستقل و بدون پروژه** فقط در وضعیت صادرشده یا تسویه‌شده طلب جدا ایجاد می‌کند. پیش‌نویس، سند باطل‌شده و پیش‌فاکتور طلب نیستند. مبلغ یادداشتی فعالیت روزانه، قیمت خدمات، مصالح و هزینه‌ها نیز خودکار به طلب پروژه اضافه نمی‌شوند.

## فاکتور و پیش‌فاکتور

اسناد شامل اطلاعات کسب‌وکار و لوگو، مشتری و پروژه، شماره، تاریخ، شرح، مقدار، واحد، قیمت و جمع ردیف‌ها هستند. تخفیف، مالیات، هزینه جانبی، سررسید یا اعتبار، شرایط پرداخت، توضیحات، تصویر QR و محل امضا در دسترس‌اند.

1. مشتری و پروژه را انتخاب و در صورت نیاز **پیشنهاد ردیف‌های قرارداد و کار اضافه** را بزنید.
2. ردیف‌ها و مبلغ را بررسی کنید؛ فاکتور با انتخاب گزینه تأیید صادر می‌شود.
3. **ذخیره و پیش‌نمایش** را بزنید.
4. از بالای پیش‌نمایش، **چاپ، اشتراک‌گذاری یا دانلود PDF** را انتخاب کنید؛ بازگشت و اصلاح سند هم در دسترس است.

اشتراک فایل از پنجره اشتراک گوشی استفاده می‌کند؛ در مرورگر فاقد این قابلیت، PDF دانلود می‌شود. چاپ دکمه‌ها را از برگه A4 حذف می‌کند. سند باطل‌شده، تسویه‌شده یا فاکتور دارای پرداخت قابل ویرایش نیست.

## نصب، آفلاین و دریافت به‌روزرسانی

**آیفون و آیپد:** برنامه را در Safari باز کنید و از منوی اشتراک، **Add to Home Screen / افزودن به صفحه اصلی** را انتخاب کنید. نام و محل گزینه ممکن است با نسخه سیستم‌عامل متفاوت باشد.

**اندروید:** از پیشنهاد نصب برنامه یا منوی مرورگر، **Install app / نصب برنامه** یا **Add to Home screen** را انتخاب کنید.

**آفلاین:** پس از بارگذاری اولیه آنلاین و آماده‌شدن کش، رابط و فونت فارسی در دسترس‌اند. نقشه آنلاین، دریافت به‌روزرسانی و نخستین نصب به اینترنت نیاز دارند. پاک‌کردن داده‌های سایت می‌تواند هم اطلاعات و هم فایل‌های آفلاین را حذف کند.

**به‌روزرسانی:** در **تنظیمات ← به‌روزرسانی برنامه**، **بررسی و دریافت به‌روزرسانی** را بزنید. اگر نسخه جدید دریافت شود، **اجرای نسخه جدید** ظاهر می‌شود؛ فرم‌های باز را ذخیره کنید و سپس آن را بزنید.

این کار فایل‌های برنامه را از طریق Service Worker به‌روز می‌کند و مشتریان، پروژه‌ها، عکس‌ها یا تنظیمات ذخیره‌شده را پاک نمی‌کند. نیازی به حذف داده سایت یا نصب مجدد نیست. در حالت آفلاین یا مرورگر فاقد پشتیبانی، پیام مناسب نمایش داده می‌شود. این امکان در بیلد منتشرشده فعال است، نه سرور توسعه معمولی Vite.

## ذخیره‌سازی، بکاپ و امنیت

- داده‌ها در **IndexedDB همان مرورگر و همان نشانی سایت** هستند. گوشی یا مرورگر دیگر خودکار آن‌ها را نمی‌بیند.
- بکاپ **نسخه ۳** شامل ۱۴ جدول، عکس‌ها، تنظیمات کسب‌وکار و تاریخچه‌هاست. نسخه‌های ۱ و ۲ با بررسی و هشدارهای سازگاری پذیرفته می‌شوند.
- بازیابی، **جایگزینی کامل** است؛ پیش‌نمایش و تأیید دارد و قبل از جایگزینی نسخه بازگشت می‌سازد. خطای نوشتن کل تراکنش را برمی‌گرداند.
- حد فایل ورودی بکاپ ۲۰۰ مگابایت است. برای داده و نسخه بازگشت باید فضای کافی موجود باشد.
- عکس JPG، PNG یا WebP تا ۲۰ مگابایت دریافت و پیش از ذخیره فشرده می‌شود. حجم storage از حجم فایل تصویر بیشتر است.
- فایل بکاپ و دیتابیس **رمزگذاری نشده‌اند**. SHA-256 برای تشخیص خرابی یا تغییر محتواست.
- قفل اختیاری رمز، کد بازیابی و قفل خودکار دارد؛ **قفل رابط محلی است، نه حساب ابری یا رمزگذاری داده‌ها**. تنظیمات قفل در بکاپ کسب‌وکار نیست.

فایل پشتیبان را خارج از همان دستگاه نیز نگه دارید. [سیاست بکاپ](docs/backup-policy.md) · [سیاست قفل](docs/lock-policy.md)

## راه‌اندازی توسعه

پیش‌نیاز: **Node.js 22.12+** و npm؛ گردش انتشار پروژه از Node.js 22 استفاده می‌کند.

```bash
git clone https://github.com/hoseindashti1981/service-project-manager.git
cd service-project-manager
npm ci
npm run dev
```

نشانی نمایش‌داده‌شده توسط Vite را باز کنید. برای توسعه معمولی، API key، حساب ابری یا فایل محیطی اجباری نیست.

```bash
npm test
npm run lint
npm run build
npm run preview
```

خروجی قابل انتشار در `dist/` ساخته می‌شود. برای آزمایش نصب و Service Worker از **build + preview** استفاده کنید.

## متغیرهای محیطی و انتشار

تنها متغیر سفارشی موردنیاز در استقرار زیرمسیر، `VITE_BASE_PATH` است. نمونه در [.env.example](.env.example) قرار دارد؛ در صورت نیاز آن را با نام `.env.local` کپی کنید.

| متغیر | پیش‌فرض | کاربرد |
| --- | --- | --- |
| `VITE_BASE_PATH` | `/` | مسیر پایه برنامه، Router، فایل‌ها و محدوده نصب PWA |

برای GitHub Pages این مخزن در PowerShell:

```powershell
$env:VITE_BASE_PATH='/service-project-manager/'
npm run build
npm run preview
```

در Bash:

```bash
VITE_BASE_PATH=/service-project-manager/ npm run build
VITE_BASE_PATH=/service-project-manager/ npm run preview
```

مقدار base در **build و preview یکسان** باشد و با `/` شروع و تمام شود. برای ریشه دامنه از `/` استفاده کنید.

[گردش GitHub Pages](.github/workflows/deploy.yml) با پوش به `main`، وابستگی‌ها را نصب، تست‌ها را اجرا، خروجی را با base صحیح بیلد و منتشر می‌کند. متغیر انتشار از قبل در workflow تنظیم شده است؛ secret اضافی برای میزبانی فعلی لازم نیست.

متغیرهای `VITE_*` در فایل مرورگر قرار می‌گیرند و عمومی‌اند؛ رمز، توکن خصوصی یا اطلاعات مشتری را در آن‌ها نگذارید. فایل‌های محیطی محلی در Git نادیده گرفته می‌شوند. تغییر origin برنامه داده محلی را منتقل نمی‌کند؛ پیش از جابه‌جایی میزبان بکاپ بگیرید.

## آزمون‌ها

`npm test` قواعد تاریخ شمسی، مبالغ، گردش کار، حساب و بکاپ را بررسی می‌کند. تست‌های مرورگر شامل گردش کار، مشتریان، فعالیت‌ها، امنیت، موبایل، عکس، اسناد و بازیابی هستند و از محیط ایزوله استفاده می‌کنند.

برای تست مرورگر، Playwright و مرورگر Edge باید در محیط آزمایش موجود باشند. مسیر فایل ورودی Playwright را در `SPM_PLAYWRIGHT_PATH` بگذارید؛ این متغیر فقط برای تست است و وارد برنامه نمی‌شود.

```powershell
$env:SPM_PLAYWRIGHT_PATH='C:/path/to/playwright/index.mjs'
# ابتدا npm run dev را در پنجره دیگر روی پورت 5173 اجرا کنید.
npm run test:browser
```

تست‌های انتشار، پس از build با base انتشار:

```powershell
node tests/app-updates.browser.mjs
# برای تست آفلاین، preview با همان base روی پورت 4174 اجرا شود.
node tests/offline.browser.mjs
```

تست به‌روزرسانی سرور محلی موقت خود را اجرا می‌کند و تغییر واقعی Service Worker، دریافت نسخه، بارگذاری مجدد و حفظ داده را می‌سنجد. برای نشانی متفاوت preview، متغیر تست `SPM_PREVIEW_URL` قابل تنظیم است. آزمون دسکتاپ جای تست نهایی Safari/PWA روی آیفون واقعی را نمی‌گیرد.

## ساختار پروژه

```text
src/app/router/       مسیرها و چیدمان برنامه
src/components/       اجزای مشترک، راهنما، قفل و به‌روزرسانی
src/domain/           مدل‌ها و قواعد حساب، گردش کار، بکاپ و امنیت
src/db/               دیتابیس Dexie و repositoryها
src/features/         صفحات مشتری، پروژه، مالی، تنظیمات و دیگر قابلیت‌ها
src/lib/              تاریخ، پول و ابزارهای مشترک
tests/                آزمون‌های واحد و مرورگر
docs/                 راهنمای کاربر، سیاست‌ها و نقشه فنی
public/               دارایی‌های عمومی PWA
```

فناوری‌ها: **React 19، TypeScript، Vite، TanStack Router، Dexie، Tailwind CSS، Workbox، html2canvas و jsPDF**. فونت فارسی Vazirmatn همراه برنامه ارائه می‌شود.

برای محاسبات، `src/domain/finance/account.ts` و `src/db/repositories/account-repository.ts` نقطه شروع‌اند. برای توسعه با AI، [نقشه فنی فارسی](docs/ai-project-map-fa.txt) را بخوانید. امکانات آینده از قابلیت‌های موجود در [نقشه راه](docs/roadmap.md) جدا شده‌اند.

## پرسش‌های رایج

**آیا فعالیت روزانه حتماً مبلغ می‌خواهد؟** خیر؛ برای شرح کار روزانه است و مبلغ و مقدار اختیاری‌اند. کار خارج از قرارداد را جدا در کار اضافه ثبت کنید.

**آیا فاکتور مبلغ پروژه را دوباره به بدهی مشتری اضافه می‌کند؟** خیر؛ فاکتور پروژه سند همان حساب است. فقط فاکتور مستقل صادرشده طلب جدا ایجاد می‌کند.

**آیا شماره مشتری باید در مخاطبان گوشی ذخیره شود؟** خیر؛ دفترچه مشتری جست‌وجو و شماره‌گیری مستقیم دارد.

**چرا اطلاعات روی گوشی دیگر دیده نمی‌شود؟** داده‌ها محلی‌اند. فعلاً انتقال با بکاپ و بازیابی انجام می‌شود؛ بازیابی ادغام نیست.

**اگر برنامه قدیمی مانده باشد چه کنم؟** آنلاین شوید و دریافت به‌روزرسانی در تنظیمات را بزنید. داده‌های سایت را برای این کار پاک نکنید.

**آیا لوگوی جدید فوراً آیکون نصب‌شده گوشی را تغییر می‌دهد؟** لزوماً خیر؛ کش سیستم‌عامل ممکن است تغییر را دیر نشان دهد یا نصب مجدد PWA لازم شود.

## English overview

**LineYar / Service Project Manager** is a Persian, RTL, local-first project and customer management PWA for field technicians and service businesses. Features include a searchable customer directory, project workflows, daily work logs, Jalali calendar, project accounting, invoice and quotation PDF previews, compressed local project photos, transactional backups and optional local app locking.

Project receivables come from the contract plus extra work minus the project discount. Project-linked invoices do not duplicate receivables. Browser data is stored locally in IndexedDB; cloud accounts and cross-device synchronization are future work. Install on a supported mobile browser, load once online for offline assets, and check for app updates from Settings without clearing business data.
